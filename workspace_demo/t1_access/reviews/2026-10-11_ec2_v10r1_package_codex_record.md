## Remaining repairs

### R1-1. Establish adopted activation and provider history

`chpc/row19_partition.py:120–122` checks the partition hash in the supplied
controls file, while CLI `:171` permits arbitrary `--controls`.
`activation_problem:153–161` checks schema, epoch, partition, manifest and
transferred indices, but ignores proof controls SHA/version, predecessor and
guard provenance. Supported trace: mint a proof using a future candidate while
canonical v9 remains active; release the lock; v9 may assign block work; adopt
the partition later. The old proof then passes. The lock alone did not establish
the claimed guard-before-scan premise.

Require the actually adopted/tracked lineage when activating, and validate proof
provenance in every consumer, with an explicit rule for retained historical
generations. A sandbox test interface must remain distinguishable from canonical
activation. Refuse malformed plan evidence rather than treating an empty plan
object as no claims (`lengau_claims:91–95`).

Later epochs also need provider-aware history. `cutover_problems:99–105` treats
every canonical record in the proposed block as Lengau completion, including
previously ingested EC2 records. Retaining completed EC2 coordinates therefore
prevents later activation; status `candidate_v10r1/row19_screen_status.py:473–474`
checks historical records against only the latest block. Validate prior epochs
and retain completed provenance; transfer only uncompleted coordinates. This is
required for the promised multi-epoch route, not a reason to stop current v9.

### R1-2. Make the inventory transition authoritative on both machines

A sealed inventory can be fresh and still obsolete. Mac disposition releases
ownership (`aws_ec2/prod_authority.py:289–294`), while a root can retain the prior
pending-owner inventory for up to six hours. Ingestion uses its `--authority`
argument; its high-water check is only against generations already consumed by
the register (`chpc/row19_ec2_ingest.py:297–312`). It does not establish that the
supplied inventory is the newest installed root view. A late bundle can therefore
publish under an obsolete owner even if no new-generation ingestion has occurred.

Install inventory transitions monotonically under the root's shared plan lock,
persist the accepted generation, and require ingestion/admission to use that
current view. Do not release/reassign Mac ownership until the root acknowledges
the corresponding disposition/fence transition. Manual scp can transport bytes;
it does not provide this handshake. Test delayed old writers and inventory
delivery out of order, including a transition with no intervening ingestion.

Require an inventory whenever an active partition or EC2 register/history is
present. Status `:402–411` leaves `inv=None` without an absence alarm when the
inventory is missing; `:461–463` then skips register/inventory membership checks.
Valid registered files can produce a clean view with `inventory_sha256=None`,
which admission accepts. Keep the genuinely empty null-partition branch valid.

### R1-4. Count finite successful paths, bind S and enforce actual release

`chpc/row19_ec2_qualify.py:79–85` calls matching `failed=False` records successful.
`analyze.py:563–581` permits checksum-valid numeric NaN/Inf, while the scientific
usable predicate `:769–771` requires finite predictor-band statistics. Matching
nonfinite records can satisfy **18/24, 36/48, 18/24** and produce RELEASE. Use the
finite predicate for the frozen statistics being qualified; retain failed and
nonfinite parity counts separately. Equal all-failed/nonfinite paths cannot
qualify successful fitting. Add contract-valid nonfinite negative fixtures.

The qualifier reads S record bodies against the scientific tasks (`:192–197`)
and hashes them (`:203–214`), but consumes no S plan, isolated operational
manifest/bindings, terminal statuses, producer generation or funding/settlement.
Correct record bodies alone do not establish the independent predeclared S
campaign. Bind and validate those artifacts, including its fixed coordinates.

`prod_authority.release_state:208–223` checks pinned certificate bytes, RELEASE
and an empty problems list, but not schema/current code, manifests, partition,
activation, plans/bundles, coverage/replay or the separate favourable
actual-result review. Its exported `released_attempts` comes from release-state
JSON rather than the validated certificate (`:245–246`); ingestion trusts that
membership (`:262–267`). A valid old certificate can survive a new declaration,
or license a different listed qualification attempt. Implement a concrete
release-adoption validator that checks the emitted contract, exact accepted
qualification and actual-result review, and derives the released attempt list.
Define the reviewed migration rule for later epochs; do not silently reuse stale
bindings. Test missing review, wrong code/partition and mismatched released keys.

### R1-5. Refuse every unproved Mac STOP absence

`aws_ec2/prod_launch.py:65–67` treats `AwsError` as failure only if its text
contains “error” or “timeout”. Endpoint connection failure or missing credentials
can lack both words and be interpreted as no STOP, in admission and recovery.
Accept only positively established absence; preserve structured return/service
information and refuse all other failures. Include those ordinary CLI failure
fixtures. AWS distinguishes configuration/credential and general failures in
its [CLI return-code contract](https://docs.aws.amazon.com/cli/latest/userguide/cli-usage-returncodes.html).

### R1-6. Demonstrate the intended packing and keep recovery scope precise

The memory gate actually computes host use and enforces at least ten samples
and at most 184 GiB (`row19_ec2_qualify.py:88–100`). The producer records memory
and occupancy every minute. Qualification does not validate sample chronology
or join it to occupancy. Bind a valid execution timeline and establish that the
samples cover intended 76-worker packing; make the actual-result review check
that evidence. Mere malformed-sample hardening is not an independent paid-launch
veto, but ten late low-occupancy samples do not prove the packing assertion.

R5 (`:103–164`) implements an experiment on a relocated, rebound copy of the
supplied Q1 bundle: interrupted **ingestion publication**, replay and second
replay with registered hashes. This favourably closes that implementation scope;
execution on actual Q1 evidence remains a future condition. It does not prove producer
process/host restart or interrupted-transfer recovery. State that distinction
and add any separately required producer recovery evidence before actual release.
The sandbox changes plan hashes, so its register is not a demonstrated way to
pass canonical Mac ACK against the original plan; do not claim that false trace.
