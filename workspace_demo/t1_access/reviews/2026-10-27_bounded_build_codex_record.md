## Blocking findings and exact fixes

**B1 — The new provenance mechanism does not always identify the implementation and catalogue actually used.** `bounded/run_point.py:54–62,118,132`; `bounded/generators.py:135–137`.

`LOADED_BOUNDED` hashes every bounded source from disk when **run_point** is imported, rather than each module binding its own digest when that module loads. An earlier import of `members` followed by a disk edit and then an import of `run_point` makes the row claim the edited source while executing the earlier member. Separately, every `run()` reads the catalogue afresh, but its digest was captured at import. A catalogue edit between rows therefore changes generating parameters without changing `config_hash` or the catalogue digest reported in `loaded_sources`.

Reproduced entirely in a scratch copy, with fitting stubbed: import members with start `log(0.3)`; change its scratch source to `log(0.7)`; import run_point. The executed start remains `−1.2039728043259361`, but its reported source digest names the edited file. Then change G13's catalogue `mu_low` from −0.1 to −0.2: both rows have hash `c7f3d36fe243` and the old catalogue digest, although the later row uses −0.2. `run(cat=...)` has the same identity problem for an explicit catalogue override. The committed smoke rows themselves are consistent; this is a reproducible production-boundary defect, not evidence that those rows were produced from changed files. Evidence: `audit:provenance_probe.py` → `provenance-probe.json`, and `audit_build.json`.

**Exact fix:** bind a source digest in each bounded module at its own import, following `models.LOADED_SOURCE_DIGEST`; assemble the identity from those bound values. Read, digest and parse the catalogue from the **same bytes**, and use that frozen parsed object for every point under that identity. An override must either be prohibited in the production API or acquire the digest of its actual canonical contents and a distinct identity. Add the two real-disk-edit regressions above. Seal the effective numerical settings and runtime in the campaign identity as well, using `analyze.numerical_snapshot()` or its equivalent; source bytes alone do not identify a changed live numerical global. Update DESIGN §2 to describe the repaired implementation and new hash.

**B2 — The qualification gates and attempted-set contract currently exist only in prose.** `bounded/run_point.py:118–125`; `bounded/calibrate.py:145–178`; `bounded/DESIGN_bounded_v1.md:111–114,118–129,137–163`.

The CLI blocks G14 when λ is null, but allows other calibration settings while the catalogue still has no boundary and every alternative has `gain_certified=false`. Validation points require no frozen calibration artifact. The calibration core accepts arbitrary raw vectors, any subset of settings and any adequate bank size; its artifact contains no configuration/runtime identity or input-row manifest. Passing a `None` correctly holds construction, but omitting a failed attempt, duplicating an identity, mixing hashes, or supplying development points is outside what this API can detect. A one-setting bank of 500 identical numeric values constructs an artifact; this is a valid mathematical helper for the supplied distribution under its assumptions, **not** enforcement of the thirty-setting qualification. The probe used stub fits, not real calibration/validation runs.

There is also no durable attempted-set record when fitting/scoring raises an exception: `procedure.py:106–108` propagates it, and `run_point.py:175–176` never reaches the row write. The smoke driver marks a subprocess failure, but is not a qualification manifest or denominator guard. An injected `FloatingPointError` reproduces the missing-row path. A missing record must not later disappear from the denominator.

**Exact fix:** keep the mathematical functions, but add a production manifest/row-ingestion boundary before qualification. It must:

1. Reserve the complete identities in advance: calibration r=0…499 for each of all 30 settings; validation r=0…399 or 0…999 as declared. Require exactly one terminal attempt record per identity, the correct namespace/seed, full member/design profile, verified deterministic digest, one frozen source/catalogue identity and the admitted runtime. Reject missing, duplicate, substituted, extra or mixed-identity inputs. Equal **values** are legitimate ties; duplicate **identities** are not.
2. Refuse every non-development setting until a finite certified boundary λ, all fourteen source-matched gain certificates, final design/numerical policy, and the benchmark admission receipt are sealed. Refuse validation until the complete calibration artifact and its input-row digest manifest have been frozen. Link decisions/validation to that artifact's digest.
3. Record numerical unavailability and aborted/crashed attempts durably. Known numerical failure is unavailable; a code/identity defect is an immediate campaign hold with its failed attempt retained. Do not turn arbitrary programming exceptions into ordinary scientific outcomes. No replacement seed or deletion of the failed identity is allowed.
4. Implement attempted-set validation counts and futility stopping: inclusion failures >21/400 or >70/1000, graded positive-or-unavailable >11/400, or power failures >160/1000 make the corresponding requirement unattainable; there is no early success.

This can be a small audited runner/assembler rather than changes to the order-statistic arithmetic. Add tests for an omitted unavailable attempt, repeated identity, wrong namespace/hash/runtime, uncertified catalogue, premature validation, and a crashing worker.

Replace DESIGN lines 127–129 exactly with: “Calibration uses the fixed 500 attempted identities per setting. Any unavailable or missing attempt holds artifact construction. Attempts are never filtered, replaced, or extended to obtain 500 successes. A numerical repair requires a new frozen algorithm and new calibration.” The present “never filtered or replaced **until** 500 successes remain” is an unsafe ambiguity.

## Non-blocking findings and scientific assessment

The train-only SD supplies the M3V floor. `logsumexp − log(member count)` averages joint densities, before division by the concept's trial count; clipping, fixed weights 27/64,22/64,15/64, and descriptive unbounded contrast are correct.
